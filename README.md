# 麻雀打牌アドバイザー（PC常駐・手動入力＋実験的画面認識）

オンライン雀卓でのプレイ中に、自分の手番で「切るならこれ」を即座に提示する
ローカル常駐ツールです。手牌効率（受け入れ枚数）に加えて、**危険牌読み（現物
・スジ・ノーチャンス・リーチ後の通過牌）と押し引き判断**まで行います。
**牌を切る操作は必ず自分で行います。自動プレイ（オートプレイ）機能は一切あり
ません。**

## スコープ・使い方についての重要な注意

- **想定用途は「AI対戦・フリー対局」限定です。** 段位戦・レート戦・課金が絡む
  対局や、他の実在プレイヤーとの真剣勝負での使用は、多くのオンライン雀卓の利用
  規約で外部ツール利用として禁止されている場合があります。使用前に、ご利用中の
  サービスの利用規約を確認し、規約に反しない範囲でお使いください。
- 本ツールが行うのは**手牌効率＋統計的な危険牌読み**です。相手の河から手役や
  染め手を推測する、点数状況（オーラスの着順条件など）を踏まえて判断する、と
  いった高度な読みは行いません。危険度は「その牌でロンされうる待ち形が、まだ
  成立しうるか」を数え上げた推定値であり、実測値ではありません（詳細は後述）。
- 画面を自動で読み取る「vision」モードは実験的機能です。オンライン雀卓ごとに
  牌のデザイン・レイアウトが異なるため、**ご利用の雀卓に合わせた個別キャリブ
  レーションが必須**であり、動作を事前に保証できません。まずは手入力モード
  （下記）から使い始めることを強く推奨します。なお、リーチの記録だけは誤認識
  を避けるため手動（`r2`）にしています。

## セットアップ

```
pip install -r requirements.txt
```

Python 3.10 以降を推奨します。`overlay` モードを使うには Tk（Windows/Mac の
公式インストーラには標準搭載）が必要です。

## 使い方

### 1. 手入力モード（`cli`） — 追加設定なしで今すぐ使えます

```
python main.py
```

自分の手牌を **mpsz記法** で入力して Enter を押すだけです。

```
> 123456789m123p1s9s
→ 切るなら: 1s  （テンパイ化！待ち: 9s）
```

- `m`=萬子, `p`=筒子, `s`=索子, `z`=字牌（1z東 2z南 3z西 4z北 5z白 6z発 7z中）
- 13枚（まだ自分の番でない時の状況確認）・14枚（ツモ後、切る牌を決める時）の
  どちらも入力できます。赤ドラは `0`（例 `0p`）でも入力できます。

牌を数える→打つまでの判断が10秒以内という前提なら、13〜14文字の入力＋Enter
は十分速く、計算自体は即時です。

#### 危険牌読みを有効にする

相手の捨て牌とリーチを教えると、効率だけでなく**放銃率と押し引き**まで出ます。
入力は毎巡ゼロから打ち直す必要はなく、**前回の自分の番からの差分だけ**を足して
いけば十分です。

| コマンド | 意味 |
| --- | --- |
| `d1 5p` / `d2 3s1z` | 下家(1) / 対面(2) / 上家(3) が切った牌を記録（複数可） |
| `d 5p 3s 1z` | 1周分をまとめて記録（下家→対面→上家の順） |
| `d0 5m` | 自分が切った牌を記録 |
| `r2` | 対面がリーチ（以降に場に通った牌も安全牌として扱います） |
| `w2` / `w2 off` | 対面を警戒（鳴き・ダマ気配）/ 解除 |
| `t 9` | 巡目の設定（押し引き判断に使用） |
| `dora 3m` | ドラ表示牌を追加 |
| `v 5p5p` | その他の見えている牌（他家の副露など）を追加 |
| `auto` / `push` / `fold` | 自動判断（既定）/ 押し優先 / ベタオリ優先 |
| `state` / `reset` / `help` | 現在の場況表示 / 新しい局としてリセット / ヘルプ |

実際の流れ:

```
> t 9
> d2 1z9p2m5m
> r2                       ← 対面リーチ
> d 3s                     ← その後、下家が3sを切って通った
> 2345699m44p567s11z
→ 切るなら: 東  [微妙]  危険度 0.0% (現物(対面))  shanten=1 受入=5種/15枚
押し引き: 微妙（押しEV -342点 / ベタオリ -372点・現物で回せます）
  対面への安全牌: 2m/5m/1z

tile   shanten     受入     危険度      EV  根拠
東            1     15    0.0%    -342  現物(対面)
2m           1      5    0.0%    -520  現物(対面)
5m           1      5    0.0%    -520  現物(対面)
9m           1     14    3.6%    -559  無スジ(対面)
4p           1     14    4.1%    -581  片スジ(対面)
```

危険度を出す相手は「リーチ(`r`)」か「警戒(`w`)」を指定した相手だけです。何も
指定していない間は純粋な効率だけを表示するので、平場では余計な情報が出ません。

### 2. オーバーレイモード（`overlay`） — 常駐して手早く入力

```
python main.py overlay
```

常に最前面に小さな入力ウィンドウが出ます。グローバルホットキー
`Ctrl+Alt+H` を押すと、ゲーム画面にフォーカスがあってもこの入力欄に一発で
フォーカスが移るので、Alt+Tab せずに打ち込めます。`Ctrl+Alt+R` で場況をリセッ
トします。入力欄は手入力モードと同じで、手牌もコマンド（`r2`, `d2 3s`, `t 9`,
`fold` など）もそのまま受け付けます。

### 3. 画面認識モード（`calibrate` / `vision`） — 実験的機能

**手牌と3人分の河を画面から読み取り、ホットキー1発で解析まで出す**モードです。
捨て牌を打ち込む手間がなくなるので、自分の番でやることは「Ctrl+Alt+M を押す」
だけになります。**事前に必ずキャリブレーションが必要**です。

#### キャリブレーション

```
python main.py calibrate
```

**[1/2] 範囲の設定**

1. 自分の手牌が並んでいる範囲をドラッグして選択
2. その範囲に入る牌の枚数を入力（ツモ後の14枚に合わせておくのが無難です。
   ツモ前の13枚でも空きマスとして正しく処理されます）
3. 各家の河の範囲を順にドラッグして選択し、列数（既定6）と段数（既定3）を入力
   - 設定した家だけ自動で読み取ります。`n` でスキップすれば手入力のままです

**[2/2] 牌画像の登録**

`h`（手牌）/ `1` `2` `3`（各家の河）を押すと、その範囲を撮影して1マスずつ
切り出し画像を表示するので、`5m` `1z` `0p`(赤5) のようにラベルを付けて登録
します。1回で34種類は揃わないので、何局かに分けて出てきた牌を足していけば
`templates/` が育っていきます。

> **重要:** 河の**空きマスを1つ `_empty` というラベルで登録**してください。
> これが無いと、まだ牌が置かれていないマスを牌と誤認します。

#### 読み取り

```
python main.py vision          # 今の画面を1回読み取って解析
python main.py vision --watch  # Ctrl+Alt+M を押すたびに読み取って解析
python main.py overlay         # オーバーレイ常駐（Ctrl+Alt+M で同じ読み取り）
```

`overlay` モードなら、結果が最前面の小窓に出るのでターミナルを見る必要があり
ません。読み取りの結果はこう表示されます:

```
対面:+3s/7p
認識した手牌: 2345699m44p567s11z

→ 切るなら: 東  [微妙]  危険度 0.0% (現物(対面))  shanten=1 受入=5種/15枚
```

1行目が「前回の読み取りから増えた捨て牌」です。**毎回河全体を読み直して、
既に記録済みの牌との差分だけを追加**するので、押すタイミングが飛んでも
（数巡ぶん溜まっても）正しく追いつきます。

鳴かれて河から消えた牌も**記録には残したまま**にしています。ポンされた牌でも
「その人が一度切った」事実は消えないので、現物判定・リーチ後の通過牌判定には
そのまま有効だからです。

#### 制限事項

- **リーチ宣言牌（横向きの牌）は読めません。** 向きが違うため、通常のテンプレ
  ートと一致しないためです。読めないマスがあると
  「リーチ宣言牌かも」と警告を出すので、`r2` のように手で記録してください。
  リーチの記録は危険牌読みの前提なので、ここだけは手動確認にしています。
- 明らかに不自然な読み取り結果（1回で7枚以上増えた等）は**採用せずスキップ**
  して警告します。誤認識で場況を壊すより安全側に倒しています。
- 牌のスキン変更・UIレイアウト変更・解像度変更のたびに再キャリブレーションが
  必要になる可能性があります。
- 赤ドラは `0p` のように登録すれば読めますが、シャンテン計算上は通常の5と同じ
  扱いです。
- 3Dで斜めに表示されるクライアントでは、河の各牌の形が歪むため認識精度が落ち
  ます。うまくいかない場合は手入力モードと併用してください（`d2 3s` のような
  コマンドはいつでも使えます）。

## 危険牌読みの仕組み

危険度テーブルを引くのではなく、**その牌でロンされうる待ち形を数え上げて**います。

1. その牌を待てる形（両面・辺張・嵌張・双碰・単騎）を列挙する
2. 成立しえない形を落とす
   - 相手がその牌自体を捨てている → **現物**（放銃率0%）
   - リーチ後に誰かが切って通っている → **通過**（同じく0%、振聴のため）
   - その形のもう一方の待ちを相手が捨てている → **スジ**（両面が消える）
   - 形に必要な牌が場に4枚見えている → **ノーチャンス**（壁）
3. 残った形を「実戦での待ち形の出現頻度」で重み付けし、必要な牌の残り枚数で
   按分する

自分の手の内にある牌も「相手が持てない牌」として計算に入るので、手牌に3枚
持っている牌のシャンポン待ちは自動的に消えます。

較正結果（対リーチ時の放銃率、カッコ内は一般に公表されている統計値）:

| 牌 | 本ツール | 公表値の目安 |
| --- | --- | --- |
| 無スジ456 | 6.5% | 約6.5% |
| 無スジ37 | 6.0% | 約6.0% |
| 無スジ28 | 5.5% | 約5.5% |
| 無スジ19 | 5.0% | 約5.0% |
| 中スジ456 | 3.1% | 約3.5% |
| スジ19 | 3.3% | 約3.2% |
| 生牌の役牌 | 4.0% | 約4.0% |
| 生牌の客風 | 3.5% | 約3.5% |
| 3枚見えの字牌 | 0.6% | 約0.5% |
| 現物 | 0% | 0% |

**押し引き**は、手牌の価値と放銃リスクを同じ「点数」の土俵に乗せて比較します。

```
押しEV = 和了率 x 平均打点 - 放銃率 x 平均放銃失点
オリEV = -(オリ切る間の残存放銃率 x 失点) - 諦めたテンパイ期待値
```

ポイントは「押しは1枚では終わらない」ことで、その牌の危険度に加えて**以降の
巡目で押し続ける分のリスク**も積算しています。だからテンパイは押し、2シャンテ
ンは微妙、それより遠い手はオリ、という常識的な結論に落ち着きます。

複数人が同時に脅威の場合は `1 - Π(1 - 各人の放銃率)` で合算します。警戒
(`w`) 指定の相手はテンパイ率をリーチの半分とみなします。

**この数値の限界:** 実戦での待ち形の分布に基づく推定であり、相手の河から手役
や打点、リーチ宣言牌の周辺（引っ掛け）を読むことはしていません。押し引きの
定数（平均打点5200〜6500点、平均放銃6000点前後など）も一般的な平均値です。
最終判断は必ずご自身で行ってください。

## テスト

```
pytest
```

シャンテン・受け入れ計算、危険牌読み（現物/スジ/ノーチャンス/リーチ後の通過牌
/較正値）、押し引きEV、コマンド解析、画面認識（グリッド分割・空きマス判定・
河の差分同期・鳴かれた牌の扱い）のユニットテストが含まれています。画面認識は
合成画像で「キャプチャ→認識→場況更新→解析」まで通した結合テストもあります。

## 仕組み（内部構成）

- `mahjong_advisor/engine/advisor.py` — シャンテン計算は実績のある
  [`mahjong`](https://pypi.org/project/mahjong/) パッケージを利用。各打牌候補
  ごとに「切った後のシャンテン数」「受け入れ牌の種類・残り枚数」を計算してラン
  キングします（`ukeire_live` = 見えている牌を考慮した残り生牌数）。
- `mahjong_advisor/engine/danger.py` — 待ち形の数え上げによる放銃率推定。
- `mahjong_advisor/engine/table.py` — 各家の河・リーチ宣言位置・通過牌の管理。
- `mahjong_advisor/engine/pushfold.py` — 押し引きの期待値モデル。
- `mahjong_advisor/session.py` — コマンド解釈の共通層。CLIとオーバーレイは
  どちらもこれを呼ぶだけなので、挙動が一致します。
- `mahjong_advisor/cli.py` / `mahjong_advisor/ui/overlay.py` — 薄い入出力層。
- `mahjong_advisor/vision/` — `mss` で画面キャプチャ、OpenCV のテンプレートマ
  ッチングで手牌と河を認識（`recognizer.py`）、読み取った河を既存の履歴と
  部分列アラインメントして差分だけ追記（`sync.py`）、それをエンジンに渡して
  解析まで通します（`runner.py`）。
