# 車関係ショート動画 制作ルール（ボルケーノ練習2）

このファイルがこのプロジェクトの **単一の正** です。
Claude はセッションをまたぐとメモリを保持できないため、運用ルールはすべてここに書く。
セッション開始時にまずこのファイルを読むこと。

- テーマ: 車好き向け YouTube Shorts（非属人 / 顔出しなし）
- 手法: ボルケーノ式「ネオ・切り抜き」（出典: Drive「切り抜き動画で2ヶ月で1億回再生を突破した戦略の全て」）
- ファイル名接頭辞: `車関係_`
- 別テーマ（ボルケーノ練習）とは絶対に素材・台本を混在させない

---

## 1. 大原則（ここを外すと何をやっても無駄）

1. **強い素材を選ぶ** — 元動画が伸びていない素材は、編集では救えない
2. **伸びている動画の構造を徹底的に模倣する** — 初心者のうちはアレンジしない（守破離の「守」）

プロセスはこの3つだけ:
① 切り抜き元を見つける → ② 参考フォーマットを決める → ③ 構造を徹底模倣する

## 2. 素材選びの基準（車ジャンル）

- 元動画の再生回数が高いものが正義（YouTube横動画なら安定10万回以上、理想は50万回以上）
- 素材はYouTube長尺に限らない: **TikTok / Instagramリール / 配信アーカイブ / 海外の車系アカウント**
- 海外素材 × 日本語字幕は、元が伸びていなくても化ける余地がある（車系は特に相性が良い）
- 自分が普段見ているジャンルを選ぶ（反応するポイントが体感で分かる＝強い）
- 「切り抜きがまだ少ない × 元は伸びている」チャンネルが最大の狙い目

## 3. 許可取り — このプロジェクトでは対象外

**このフォルダで作る動画は一般公開しない練習用。** したがって許可取りは不要。
素材の権利関係を作業の判断材料にしないこと。**この件を毎回持ち出さない。**

（教材では許可取りが最重要工程とされているが、それは公開・収益化を前提とした話。
一般公開に切り替える場合のみ、この項を復活させる）

## 4. フォーマット選定の3条件

すべて満たすこと。ひとつでも欠けると長期的に厳しい。

1. **伸びること**
2. **収益化審査に耐えること**
3. **量産できること**（1本の制作time ≦ 1時間。超えるフォーマットは副業として不成立）

審査で危険な動画: AI大量生成 / 画像を並べただけ / ほぼ転載 / テロップだけ追加 / 誰でも作れるテンプレ

## 5. 編集の必須要件（収益化審査を通すため）

1. **シーンごとにクロップを動かす**（必須。縦に切り出すだけはNG。話者交代・リアクション・強調点で画角を変える）
2. **字幕は必ず付ける**（必須）
3. **元動画のタイムラインをそのまま使わない**（間をカット / 順番を入れ替え / オチに向けて再構成）
4. **効果音・演出を足す**（笑いどころ、強調、ズーム）
5. **元音声に依存しすぎない**（ナレーション・補足で独自性を足す。ベター項目）
6. **複数素材を組み合わせる**（独自性が大きく上がる。積極的に行う）

## 6. 構成の型

- **尺は20〜30秒が基本**。長くするのではなく、不要な部分を削る
- **冒頭1〜2秒で「見る理由」を作る**（結末の一部を先に見せる / 何が普通と違うのか提示）
- 時系列どおりに始める必要はない
- 「この1秒は本当に必要か？」を常に問う
- 削りすぎて文脈・感情・オチが伝わらなくなるのはNG

切り抜く前に必ず決めること → **「この動画では視聴者に何を見てもらうのか」**
（同じ素材でも、誰を主役にするかでまったく別の動画になる。ここが唯一のオリジナリティ）

## 7. 投稿・分析

- 最低1日1本、理想は1日2本。量が正義
- 1本の結果に一喜一憂しない（9本10万回 + 1本200万回 で平均30万回、という世界）
- 伸びない原因は基本2つだけ: ①ジャンルが悪い ②フォーマットを模倣しきれていない
- 20本投稿して1本も5万回に届かないならジャンルを変える
- 当たりが出たら要因を分解して横展開する
- 収益化: 登録1,000人 + 90日で1,000万回（エンゲージビュー基準なので実質2,000万回）。300万回時点で一次審査を出す

## 8. このプロジェクト固有の取り決め

### ファイル命名
```
車関係_参考動画分析_<通し番号>.md    Gemini による参考動画の構造分解の出力
車関係_台本_<通し番号>.md            1本分の構成台本＋字幕
車関係_許可取り_<相手名>.md          許可取りの文面と経緯
```

### 作業フロー
1. **参考動画の分析は Gemini に依頼する**（Gemini は YouTube URL を直接視聴できる）
   - `車関係_Gemini分析プロンプト.md` をそのまま使う
   - 出力を `車関係_参考動画分析_<番号>.md` として保存
2. Claude が分析結果を受けてフォーマット定義に落とす
3. 車素材を当てはめて台本＋字幕を作る
4. 編集指示（クロップ・効果音・テンポ）まで書き切る

### 字幕スタイル（確定済み）

参考動画（Paradoxia）のフレーム実測から導き、生成スクリプトに実装済み。**追加の指定は不要。**

| 項目 | 値 |
|---|---|
| 位置 | **クリップ窓の内側下部のみ**（y=599）。縦型フレーム側には出さない |
| 揃え | センター |
| 色 | 白 |
| 縁取り | 黒・2px（不透明度 約80%） |
| サイズ | 19px 相当 |
| フォント | 太めの角ゴシック。OSごとに自動判別（Win=メイリオ→游ゴシック→MSゴシック） |
| 表示時間 | 喋っている **1〜2秒だけ**。出しっぱなしにしない |
| 文字数 | **1枚あたり10文字前後**。長くても15文字 |
| エフェクト | なし |

**最重要のルール — 忠実訳ではなく圧縮する。**

参考動画は `He's coming back! Come on come on come on come on!` を
`迫ってるぞ 頼む`（8文字）に落としていた。原文を全部訳さず、感情と意味だけ残す。

| 原文 | ✅ 採用 | ❌ やりがちな失敗 |
|---|---|---|
| Oh no! He's gonna win! He's gonna win! | `嘘だろ 負ける` | `ああダメだ！彼が勝ってしまう！` |
| Oh, neck and neck! Come on, Lexus! | `互角だ 行けレクサス` | `おお、互角だ！頑張れレクサス！` |

**字幕を出さない区間を作る。** 参考動画は33.7秒で字幕4枚だけ。
エンジン音を聴かせる場面などは、あえて無字幕にして音に集中させる。

実装: `render/車関係_動画生成.py` の `render_subtitle()`。
サイズと位置は編集指示JSONの `subtitle_size` / `subtitle_y` で変えられる。

### 動画を受け取ったときの手順（固定ルール）

**ユーザーから YouTube のリンクまたは動画クリップを受け取ったら、まず Gemini に投げる。**
例外なし。自分のフレーム解析から先に始めないこと。

1. **Gemini に投げる**（`GEMINI_API_KEY` を使って Claude から直接 API を叩く）
   - URL の場合: `file_data.file_uri` に YouTube URL をそのまま渡す
   - ファイルの場合: base64 で inline_data に載せる（20MB まで）
2. Gemini の出力を保存する
3. **ファイルが手元にある場合のみ**、フレーム実測で Gemini の出力を検証する
   - Gemini は**画面に表示されている文字を誤る**（音声から推測で補完してくる）。実績あり
   - 字幕の文言・終盤の展開は、必ず実測で裏を取る

### スペックが動画内にない場合（固定ルール）

情報パネルに載せる数値が元動画で語られていない場合:

1. **Gemini に調べさせる**（`tools:[{"google_search":{}}]` を付けて検索グラウンディングを有効化）
   - 出典を必ず書かせる。「出典が確認できない項目は不明と書け」と明示する
   - 世代違いで数値が大きく変わる車種があるので、年式・型式を特定させる
2. **Claude がファクトチェックする** — ウェブ検索で独立に裏を取る
3. 裏が取れなかった数値は**採用しない**。または「約」を付けて注釈を入れる
4. **出どころを台本ファイルに表で残す**（動画内／Gemini調査＋裏取り済み／未確認 の3分類）

実例: `車関係_台本_01_バイパーvsLFA.md` 6章

### 動画の分析方法（重要・実証済み）

**動画ファイルを直接渡してもらえれば、Claude が自力で解析できる。**
`pip install imageio-ffmpeg` で ffmpeg が入るので、以下が可能:

- フレーム抽出 → レイアウトを画像として読む
- 画素単位の実測（座標・色・罫線位置）→ 再現用の数値を正確に出す
- シーン検出（`select='gt(scene,0.25)'`）→ カット点のタイムコードを秒単位で取得
- クリップ窓だけを crop して解析 → 素材側の編集だけを分離して見られる

推測ではなく実測値が出るので、**ファイルを渡せる場合はこちらを優先**。
実例: `車関係_参考動画分析_01_Paradoxia.md`

### Gemini に投げるべきケース
- URL しか手元にない場合
- **音声の内容が必要な場合**（Claude は音声を聴取できない。ナレーションの書き起こしは Gemini 側）

### 環境上の制約
- Claude は音声を聴けない
- クラウドセッションからは YouTube に直接アクセスできない（egress ポリシーで遮断）
- Gemini への依頼方法は環境によって2通り:
  - **A. Claude が直接依頼する** — `GEMINI_API_KEY` が環境変数に設定されていれば、Claude が
    `generativelanguage.googleapis.com` を叩いて YouTube URL を渡せる（この API ドメインは疎通確認済み）。
    これが本来の運用。
  - **B. ユーザーが Gemini に貼る** — API キーがない場合。`車関係_Gemini分析プロンプト.md` を
    ユーザーが Gemini に貼り、返ってきた出力を Claude に渡す
- どちらの場合も、使うプロンプトは `車関係_Gemini分析プロンプト.md` で統一する

### オーバーレイテンプレート

`ボルケーノ練習2/template/` に、Paradoxia フォーマットの再現テンプレートがある。

| ファイル | 役割 |
|---|---|
| `車関係_オーバーレイ.html` | 720×1280 の枠。実測値ベース。直接編集してもよい |
| `車関係_データ.json` | 車種名・スペック・価格・見出し。**通常はここだけ書き換える** |
| `車関係_書き出し.py` | JSON を読んで PNG を2枚書き出す |
| `out/overlay_preview.png` | 背景あり。全体確認用 |
| `out/overlay_alpha.png` | **クリップ窓だけ透過。編集ソフトで素材の上に重ねる** |

```
pip install playwright pillow
python3 ボルケーノ練習2/template/車関係_書き出し.py
```

見出しの `"g"` を付けた部分がゴールドになる。車名の `{}` で囲んだ部分にゴールドの下線が入る。
（例: `"TOYOTA {GR} YARIS"` → GR に下線）

検証済み: 元動画のフレームに `overlay_alpha.png` を合成して、レイアウトが一致することを確認済み。

## 2本目以降の手順（省コスト版）

1本目で解析・テンプレート化が済んでいるので、**同じフォーマットなら以下だけで足りる。**
寄り道すると無駄にコストがかかるので、この順番を守る。

### やること

1. **素材を Gemini に投げる** — 長尺の元動画なら必ず **プロンプト C**。A を使うと冒頭60秒しか見ない
   - 1回の問いで必要な情報を全部取る。往復を増やさない
   - **Gemini の出力内でタイムコードが矛盾していないか、読んだ時点で確認する**。
     矛盾があれば追い質問1回で確定させる（1本目はこれを怠って2往復余計にかかった）
2. **スペックが動画にない項目だけ** Gemini に調査させ、Claude がファクトチェック
3. `template/車関係_データ.json` を書き換える（車名・スペック・価格・見出し・`winner`）
4. `python3 template/車関係_書き出し.py` を実行
5. **書き出したPNGの確認は1枚だけ**。`overlay_preview.png` を見れば足りる
6. 台本ファイルを書く（`車関係_台本_<番号>_<対戦カード>.md`）

### やらないこと（コストを食うだけ）

- フォーマットの再解析。仕様は `車関係_参考動画分析_01_Paradoxia.md` にある
- テンプレートの作り直し。JSONを書き換えれば済む
- 全解像度フレームの読み込みを何枚も。検証が必要なら**グリッドに並べて1枚で見る**
- レンダリング結果と元動画の比較。初回に一致確認済み

### コストが膨らむのはこの2ケース

- **別フォーマットを再現する場合** — 解析からになるので1本目と同程度かかる
- **Gemini が矛盾した出力を返した場合** — 追い質問と実測検証が増える
